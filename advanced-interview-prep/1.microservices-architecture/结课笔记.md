# 微服务架构 · 结课笔记

## 两个根（一切皆由此推导）

1. **收益 = 独立可部署性**（组织决策，不是代码风格）。拆分买的是「一个服务自己改、自己测、自己上」。判断一切边界与成败的最终标准。
2. **天条：进程内调用 → 网络消息**。两台机器不共享命运、内存、锁、时钟，之间只有会丢、会延迟、会重复、会乱序的消息。微服务的全部复杂性是这一条物理事实的推论。

## 三条后果链

### 消息链：三态 → 幂等 → at-least-once → Outbox

- **超时三态**：成功 / 失败 / **未知**。放弃等待 ≠ 取消执行——B 的活一旦开始就会跑完。
- **幂等**：执行 N*N* 次 = 执行 1 次。幂等键跟着**业务操作**走（重试带同一个键）；去重记录与业务写**同一个本地事务**（唯一约束当裁判）；重复请求**返回首次结果**而非报错；设值式（`SET x = v`）天然幂等，增量式必须靠键。
- **投递语义**：丢（不可恢复）vs 重复（可修复）→ 永远选 at-least-once。**at-least-once + 幂等消费 = 恰好一次「生效」**。Kafka「exactly-once」只覆盖「读 Kafka → 写回 Kafka」的内部链路，副作用出界即退化。
- **Outbox（本地消息表）**：业务表 + outbox 表一个本地事务，relay 搬运 → 把不可接受的双写窗口换成可修复的重复。

### 资源链：Little 定律 → 传染 → 四件套

L=λW(在途=速率×时延)*L*=*λW*(在途=速率×时延)

- **下游的延迟就是你的资源占用**；延迟是乘数，W*W* 涨 10 倍资源需求涨 10 倍。**慢比死危险**（宕机 1ms 释放线程，慢占 30s）。
- 四件套对应定律三个变量：**超时**钳 W*W*（生死线，非可选）；**舱壁**隔离 L*L*；**熔断**砍 λ*λ*（半开 = 少量试探恢复）；**重试纪律**（退避 + 抖动 + 预算——重试是流量的乘数）。
- 落地分层：南北向（进系统）归**网关**（限流/卸载）；东西向（服务间）归**调用方进程内**（Resilience4j）或 **sidecar**（Istio，动态规则免发版）；Sentinel = 动态规则 + 流量治理全家桶。

### 可用性链：乘法 → 降级 / 异步

- 串联、扇出（全部需要时）都相乘：0.999n0.999*n*。**关键路径长度是架构预算**；非关键依赖要可降级。
- **同步/异步判据**：需要答案才能继续 → 同步；只是传递事实 → 异步。**关机试验**：把下游关掉，这次操作还成功吗？成功才是真异步。MQ 发消息再阻塞等响应 = 假异步，代价更高解耦为零。

## 数据链

- 数据私有 → 无全局锁 → 2PC 被否（prepare 持锁、协调者单点、可用性相乘）→ **Saga**：本地事务串 + 补偿。
- **Saga 结构性放弃隔离性**：每步真实提交，中间态对外可见。原子性靠补偿**工程逼近**（补偿可失败），隔离性没有替身——单机事务是**批发保护**（守住所有不变量含没想到的），Saga 是**零售守卫**（条件更新、乐观锁，逐个手工武装），且**可见性**零售守卫够不着。
- 手工重建三砖：**状态机**（中间态语义化）、**TCC**（冻结 = 显式预留，解冻必成功）、**对账**（承认零售必漏的最后防线）。
- 补偿不是撤销，是**新的业务动作**；不可逆动作（发短信）排最后。
- 协调器自己也会死：**状态机每步持久化 + 幂等重放**，恢复 = 读状态机继续。

## 边界与分布式单体

- 判据一：**变化落在服务内**；判据二：**切口绕开昂贵的**（交换事实=便宜，交换答案=贵，要强一致=这刀可能切错了）。
- 共享 Schema = 假边界；康威定律：系统长成组织的沟通结构。
- **分布式单体**：付了全部账单，没拿到商品，比单体还差。唯一标志：**能独立上线吗？** 修法是重认边界，不是加基础设施。

## 事故响应次序

**回滚可疑变更 / 切断传染 → 恢复服务 → 治根复盘。** 凌晨两点能掏出什么武器，取决于三个月前埋了什么——韧性控制必须内建且运行时可调。
